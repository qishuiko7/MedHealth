## 二、环境准备（对应流程步骤 1~3）

### 2.1 步骤 1：安装 VMware Workstation

1. 到 VMware 官网下载 Workstation Pro（个人教学免费），一路默认安装。
2. 安装完成后打开，`文件 → 新建虚拟机 → 自定义(高级)`。
3. 也可先用 `vmware` 命令行检查版本：`vmware -v`。

### 2.2 步骤 2：安装 FinalShell

1. 下载 FinalShell（Windows 版），一路默认安装。
2. 打开后：`SSH 连接 → 新建连接`，填写：
   - 名称：`hadoop01`
   - 主机：虚拟机 IP（见 2.4）
   - 端口：22，用户名：`root`，密码：安装时设置
3. 保存后可双击连接；底部可打开 SFTP 面板上传安装包。

### 2.3 步骤 3：VMware 中部署 CentOS

**虚拟机规格建议（单节点伪分布式）**

| 资源 | 最低 | 推荐 |
|---|---|---|
| CPU | 2 核（开启虚拟化） | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 40 GB | 60 GB（SCSI，单文件） |
| 网络 | NAT | NAT（便于外网，且 Windows 可经 VMnet8 访问） |

**CentOS 安装要点**

1. 新建虚拟机时选择 `稍后安装操作系统`，客户机系统选 `Linux / CentOS 7 64 位`。
2. 挂载 CentOS-7-x86_64-DVD ISO，启动进入安装界面。
3. 分区：选择 `自动分区`（或手动：`/boot 1G`、`swap 8G`、`/ 剩余`）。
4. 软件选择：`基础设施服务器` 或 `最小安装` + 右侧勾选 `开发工具`（保证有 gcc/make）。
5. 网络：安装时即可开启网卡 (`网络和主机名 → 打开`)，主机名设为 `hadoop01`。
6. 设置 root 密码（如 `root123456`），创建用户可省略（脚本会创建 `hadoop`）。
7. 安装完成后重启，用 root 登录。

**关闭防火墙与 SELinux（脚本 01 已做，手工版）**

```bash
# 关闭防火墙
systemctl stop firewalld && systemctl disable firewalld
# 关闭 SELinux
setenforce 0
sed -i 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config
```

### 2.4 静态 IP 配置（关键，务必固定）

查看网卡名：`ip addr`（常见 `ens33`）。

```bash
vi /etc/sysconfig/network-scripts/ifcfg-ens33
```

修改/新增（其余保持默认）：

```ini
BOOTPROTO=static
ONBOOT=yes
IPADDR=192.168.10.101
NETMASK=255.255.255.0
GATEWAY=192.168.10.2
DNS1=223.5.5.5
```

> VMware NAT 网关通常为 `xxx.xxx.xxx.2`，可在 `编辑 → 虚拟网络编辑器 → VMnet8 → NAT设置` 中确认；Windows 的 `VMnet8` 虚拟网卡需与虚拟机同网段（如 192.168.10.1）。

重启网络并验证：

```bash
systemctl restart network
ip addr show ens33
ping -c 3 www.aliyun.com
```

**Windows 端测试连通（宿主机 CMD）**

```cmd
ping 192.168.10.101
```

### 2.6 创建 hadoop 用户与免密登录

```bash
# 创建用户与组
groupadd hadoop
useradd -m -g hadoop hadoop
echo "hadoop:hadoop123" | chpasswd
echo "hadoop ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/hadoop
chmod 440 /etc/sudoers.d/hadoop

# 免密登录（切换 hadoop 用户）
su - hadoop
ssh-keygen -t rsa -b 4096 -N '' -f ~/.ssh/id_rsa
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
# 自测
ssh hadoop01
```

**三节点扩展**：在每台机器生成密钥后，用 `ssh-copy-id` 互相分发：

```bash
for h in hadoop01 hadoop02 hadoop03; do ssh-copy-id $h; done
```

### 3.1 步骤 4：部署 JDK 与 MySQL

#### 3.1.1 安装 JDK 8

```bash
cd /opt/software
# JDK 需从 Oracle 官网下载（需登录），离线拷贝到此处
tar -zxf jdk-8u381-linux-x64.tar.gz -C /opt/module/
mv /opt/module/jdk1.8.0_381 /opt/module/jdk1.8.0_381   # 目录名一般已是此名
```

配置全局环境变量（`/etc/profile.d/bigdata_env.sh`）：

```bash

export JAVA_HOME=/opt/module/jdk1.8.0_381
export HADOOP_HOME=/opt/module/hadoop-3.3.6
export HIVE_HOME=/opt/module/hive-3.1.3
export ZOOKEEPER_HOME=/opt/module/zookeeper-3.8.4
export KAFKA_HOME=/opt/module/kafka_2.12-3.6.1
export SPARK_HOME=/opt/module/spark-3.5.1-bin-hadoop3
export PATH=$JAVA_HOME/bin:$HADOOP_HOME/bin:$HADOOP_HOME/sbin:$HIVE_HOME/bin:$ZOOKEEPER_HOME/bin:$KAFKA_HOME/bin:$SPARK_HOME/bin:$SPARK_HOME/sbin:$PATH
export HADOOP_CONF_DIR=$HADOOP_HOME/etc/hadoop
export HIVE_CONF_DIR=$HIVE_HOME/conf
export LD_LIBRARY_PATH=$HADOOP_HOME/lib/native:$LD_LIBRARY_PATH
EOF
source /etc/profile.d/bigdata_env.sh
java -version   # 预期：java version "1.8.0_381"
```

#### 3.1.2 安装 MySQL

```bash
# 方式A：官方源（MySQL 8.0）
yum install -y https://dev.mysql.com/get/mysql80-community-release-el7-1.noarch.rpm
yum install -y mysql-community-server mysql-community-client

# 方式B：系统自带（CentOS 8/9）
# yum install -y mysql-server
# 方式C：CentOS 7 无官方源时用 MariaDB
# yum install -y mariadb-server mariadb

systemctl enable mysqld --now
# MySQL 8 首次启动会生成临时密码
grep 'temporary password' /var/log/mysqld.log
```

设置密码、创建 Hive 元数据库与业务库：

```sql
-- 登录：mysql -uroot -p
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'root123456';
CREATE USER 'root'@'%' IDENTIFIED WITH mysql_native_password BY 'root123456';
GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION;

-- Hive 元数据库
CREATE DATABASE hive_meta DEFAULT CHARACTER SET utf8mb4;
CREATE USER 'hive'@'%' IDENTIFIED WITH mysql_native_password BY 'hive123456';
GRANT ALL PRIVILEGES ON hive_meta.* TO 'hive'@'%';

-- 业务库
CREATE DATABASE med_health DEFAULT CHARACTER SET utf8mb4;
CREATE USER 'med'@'%' IDENTIFIED WITH mysql_native_password BY 'med123456';
GRANT ALL PRIVILEGES ON med_health.* TO 'med'@'%';
FLUSH PRIVILEGES;
```

放开远程访问（Windows 端需要连）：

```bash
vi /etc/my.cnf
```

在 `[mysqld]` 段加入：

```ini
bind-address = 0.0.0.0
default_authentication_plugin = mysql_native_password
character-set-server = utf8mb4
collation-server = utf8mb4_general_ci
default-time-zone = '+08:00'
```

```bash
systemctl restart mysqld
# 验证
mysql -uroot -proot123456 -e "SHOW DATABASES;"
```

**Spark Structured Streaming 最小骨架（供参考）**

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import from_json, col, window
from pyspark.sql.types import StructType, StringType, IntegerType

spark = (SparkSession.builder
         .appName("med_realtime")
         .config("spark.sql.shuffle.partitions", "4")
         .getOrCreate())

schema = StructType().add("patient_id", StringType())\
                     .add("dept_name", StringType())\
                     .add("ts", StringType())

raw = (spark.readStream.format("kafka")
       .option("kafka.bootstrap.servers", "hadoop01:9092")
       .option("subscribe", "med_registration")
       .option("startingOffsets", "latest")
       .load())

parsed = raw.select(from_json(col("value").cast("string"), schema).alias("d")).select("d.*")

query = (parsed.writeStream
         .outputMode("append")
         .foreachBatch(lambda df, eid: df.write
                       .format("jdbc")
                       .option("url", "jdbc:mysql://<Windows-IP>:3306/med_health")
                       .option("dbtable", "ods_registration_rt")
                       .option("user", "root").option("password", "root123456")
                       .mode("append").save())
         .trigger(processingTime="30 seconds")
         .start())

query.awaitTermination()
```

## 八、常见问题与排错

### 1. NameNode 未格式化 / 重复格式化导致 DataNode 不启动
- 现象：`jps` 有 NameNode 无 DataNode；日志报 `clusterID mismatch`。
- 原因：重复 `hdfs namenode -format` 会生成新 clusterID，旧 DataNode 数据目录不匹配。
- 处理：停止集群 → 删除 `/data/hdfs/name` 与 `/data/hdfs/data` 全部内容 → 重新 `hdfs namenode -format` → `start-dfs.sh`。
- 预防：只格式化一次；脚本 03 已做幂等判断。

### 2. DataNode 不启动（slaves/workers 配置错误）
- 现象：`jps` 缺 DataNode；`workers` 内容不对。
- 处理：确认 `$HADOOP_HOME/etc/hadoop/workers` 中主机名与 `/etc/hosts` 完全一致；Hadoop 3.x 用 `workers`（不是 `slaves`，两者可同时存在以防混用）。

### 3. Hive 元数据库连接失败
- 现象：`schematool` 报 `Communications link failure` 或 `Access denied`。
- 排查：
  1. MySQL 是否启动：`systemctl status mysqld`；
  2. `hive-site.xml` 的 URL/用户名/密码是否正确；
  3. 是否放入 `mysql-connector-j-8.0.33.jar`；
  4. MySQL 用户是否允许从本机连接（`'hive'@'localhost'` vs `'hive'@'%'`）；
  5. MySQL 8 认证插件：用 `mysql_native_password`。
- 处理：`mysql -hhadoop01 -uhive -phive123456 -e "show databases"` 先行验证连通性。

### 4. Hive 与 Hadoop 的 guava 版本冲突
- 现象：`NoSuchMethodError: com.google.common.base.Preconditions.checkArgument`。
- 处理：删除 `$HIVE_HOME/lib/guava-19.0.jar`，复制 `$HADOOP_HOME/share/hadoop/common/lib/guava-27.0-jre.jar` 到 Hive lib（脚本 04 已处理）。

### 5. Kafka 与 ZooKeeper 版本不兼容
- 现象：Kafka 启动即退出，日志 `KeeperErrorCode` 或连接超时。
- 处理：确认 `zookeeper.connect` 与 ZK 地址、端口一致；Kafka 3.6.1 支持 ZK 模式，ZK 3.8.x 兼容；若用 Kafka 4.x 则必须 KRaft（不再用 ZK）。查看 `/tmp/kafka-start.log`。

### 6. Spark 找不到 Hive 表（`Table or view not found`）
- 原因：Spark 未加载 Hive 配置或 `hive-site.xml` 未软链。
- 处理：
  1. `ln -sfn $HIVE_HOME/conf/hive-site.xml $SPARK_HOME/conf/hive-site.xml`；
  2. `spark.sql.catalogImplementation=hive`；
  3. 提交时 `export SPARK_DIST_CLASSPATH=$(hadoop classpath)`；
  4. 需 `--files`/`--jars` 时把 hive-site.xml 一起带上。

### 7. Windows 端连不上 Linux MySQL
- 现象：PyMySQL 报 `Can't connect to MySQL server (10060)` / `1045`。
- 处理：
  1. Linux `bind-address = 0.0.0.0`；
  2. 授权 `'root'@'%'`（或业务账号）；
  3. 关闭 Linux 防火墙（`systemctl stop firewalld`）；
  4. VMware 网络为 NAT 时确认 Windows 能 `telnet 192.168.10.101 3306`。

### 8. 时间不同步导致 YARN / Hadoop 异常
- 现象：作业提交失败、日志时间错乱、Kerberos（若启用）认证失败。
- 处理：所有节点启用 `chronyd` 指向同一 NTP，`chronyc sources -v` 检查；偏差 > 阈值会导致 RPC 校验失败。

### 9. 端口被占用导致组件起不来
- 排查：`ss -lntp | grep <端口>` 或 `netstat -anp | grep <端口>`。
- 典型：8080 被 ZooKeeper AdminServer 或 Spark Master 占用；解决方案是关闭 ZK adminServer 或改 Spark 端口。
- 处理：`kill -9 <pid>` 后重启，或修改对应配置端口（全局端口见 1.2）。

### 10. 防火墙未关闭导致组件间通信失败
- 现象：HDFS/Spark 能启动，但跨机通信超时。
- 处理：`systemctl stop firewalld && systemctl disable firewalld`；临时验证可 `setenforce 0`。

### 11. 中文乱码（Hive/MySQL/前端）
- 现象：查询结果中文显示 `???`。
- 处理：
  1. MySQL 库/表字符集 `utf8mb4`，连接串加 `characterEncoding=UTF-8`；
  2. Hive 建表 `ROW FORMAT DELIMITED` 时指定 `SERDEPROPERTIES('serialization.encoding'='UTF-8')`；
  3. Python 读写统一 `encoding='utf-8'`；
  4. 前端页面 `<meta charset="utf-8">`。

### 12. `schematool` 反复失败 / 元数据库半初始化
- 现象：首次初始化中断，再次初始化报 `Table already exists`。
- 处理：`mysql -e "DROP DATABASE hive_meta; CREATE DATABASE hive_meta;"` 后重新 `schematool -dbType mysql -initSchema`。

### 13. YARN 容器因内存被 kill
- 现象：Spark/MapReduce 任务报 `Container killed on request. Exit code 137`。
- 处理：`yarn.nodemanager.pmem-check-enabled=false`、`vmem-check-enabled=false`（脚本已设）；并调低 `--executor-memory` / `spark.yarn.executor.memoryOverhead`。

### 14. HDFS 处于 Safe Mode（安全模式）
- 现象：写 HDFS 报 `Name node is in safe mode`。
- 处理：`hdfs dfsadmin -safemode leave`；若因副本不足导致，等待 DataNode 上报或调低 `dfs.replication`。

### 15. Spark on YARN 报 `No suitable driver` 或找不到 MySQL 驱动
- 处理：`spark-submit --jars mysql-connector-j-8.0.33.jar`，或在 `spark-defaults.conf` 中 `spark.jars` 指定；JDBC URL 用 `com.mysql.cj.jdbc.Driver`。

### 16. FinalShell 连接超时
- 处理：确认虚拟机 `sshd` 运行（`systemctl status sshd`）、IP 正确、VMnet8 网段匹配、防火墙放行 22 端口。
